# 系统运维与迁移

**[English](OPERATIONS.en.md)**

## 新电脑迁移检查清单

1. 复制完整项目目录，包括 `.env`、`data`、`storage`、`exports`、`backups`、`models` 和 `tools`。
2. 安装 Python 3.12 或更高版本，然后运行一次 `setup.bat`。
3. 如需本地 AI，确认 `data/student_management.db` 存在，并确认模型清单或 GGUF 文件已一并迁移。
4. 运行 `start-system.bat`，访问 `http://127.0.0.1:8100`。
5. 登录后核验学生总数、一个原始资料、一次导出预览、AI 状态和最近备份。

迁移时不要删除 `.env`。其中包含让现有数据库和加密数据可继续读取的 JWT 与数据加密配置。

## HTTPS 部署

应用应保持绑定在 `127.0.0.1`，由反向代理提供 HTTPS。Caddy 的最小示例：

```text
students.example.edu {
    reverse_proxy 127.0.0.1:8100
}
```

服务器 `.env` 至少设置：

```text
ENVIRONMENT=production
COOKIE_SECURE=true
JWT_SECRET=<new-long-random-secret>
DATA_ENCRYPTION_KEY=<stable-fernet-key>
```

代理负责证书与 HTTPS。不要向公网暴露 3306 或 11434；防火墙只应允许反向代理和受信任管理网络访问。

## 备份与恢复

从 **系统设置 → 数据库备份** 创建备份。正式依赖备份前，应先执行 **校验** 和 **演练**。演练会在隔离位置解压并核验副本，不会修改正在使用的数据库。真实恢复会先创建恢复点并写入审计记录；恢复后应重启应用，并核验学生数量和 AI 状态。

备份删除与导出清理互不影响。导出清理只删除超过保留期的 `.xlsx` 或 `.csv`，不会删除原始资料、学生档案、模型文件或数据库备份。

## AI 使用边界

本地模型只负责规划自然语言查询和解释结果。数据库查询、汇总、来源标注、导出确认和权限检查都由服务端执行。AI 不能修改或删除数据库；涉及修改的需求必须在系统页面中手动完成。

管理员可以在 **审计与 AI 记录** 查看调用人、问题、输出、数据来源、模型名称和响应时间。AI 与审计记录仅向管理员和超级管理员开放。

## 日常核验

- 使用模型辅助导入前，检查 AI 指示器是否为可用状态。
- 每次 Word 或相关 Excel 导入后检查学生相关信息审核队列。
- 使用导入报告和错误 CSV 处理未匹配行；无法处理的记录进入人工匹配队列。
- 查看系统告警和失败后台任务。
- 恢复备份后运行审计链完整性校验。
- 使用超级管理员系统状态面板关注磁盘占用并清理过期导出文件。

## 离线依赖

Lucide 图标由 `app/static/vendor/lucide.min.js` 本地提供。项目内 Ollama 运行时和模型位于 `tools/ollama`、`models/ollama` 或 `models/imports`。这些目录迁移完成后，日常启动无需访问互联网；Python 依赖必须已存在于 `.venv` 或可从受控镜像源获得。
